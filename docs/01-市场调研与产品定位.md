# 跨境独立站物流运费：有没有现成工具？

> 调研时间：2026-11 · 目标：搞清楚「WordPress + WooCommerce 跨境发货、按货代报价单算运费」这件事，市面上到底有没有现成方案。

## 一句话结论

**有零件，没有整机。**

通用「费率表」插件很多，能按国家/重量配价格；少数物流商有官方对接插件，能调 API 出价。
但**没有一款是围绕「国内货代的报价单」设计的**——也就是把一张 Excel 分区表直接变成运费规则，
自动处理分区、重量段、挂号费、操作费、最低消费、燃油、偏远、体积重、汇率这一整套。

你要的功能，散在 3～4 个插件里，每个都要手工填一遍数据。

---

## 现有方案盘点

### 1. 通用费率表插件（最接近，但都不是为跨境报价单做的）

| 插件 | 能做什么 | 缺什么 |
| --- | --- | --- |
| [Table Rate Shipping for WooCommerce](https://codecanyon.net/item/table-rate-shipping-for-woocommerce/3796656)（Bolder Elements / Barn2 系） | 按重量/件数/金额/目的地配区间价 | 一档一档手填，没有「分区 + 挂号费 + 每公斤单价」的概念，不能导报价单 |
| [Flexible Shipping](https://wordpress.org/plugins/flexible-shipping/)（WPDesk） | 重量/金额区间、条件规则 | 同上；按公斤计价要自己换算成档位 |
| [Shipped – Table Rate Shipping](https://wordpress.org/plugins/table-rate-shipping-rates/) | 22 种费用组合、邮编/州规则 | 面向本土配送，无体积重、无燃油/挂号费 |
| [WowShipping](https://wordpress.org/plugins/wow-table-rate-shipping/) | 按重量的阶梯价 + UPS/USPS/DHL 实时价 | 阶梯价是「固定价 + 每 kg 加价」，不是分段查表 |
| [YeeShipping](https://zh-hk.wordpress.org/plugins/yeeshipping/) | **有体积重**（长×宽×高÷系数），取实重与体积重较大值 | 只是费率表 + 体积重，没有分区导入、没有挂号费/操作费 |
| [Erapex Shipping](https://fair.pm/packages/plugins/erapex-shipping/) | 重量/金额/目的地/配送类规则，支持 CSV 导入导出 | CSV 是「规则行」，不是货代报价单格式；仍然要逐条组织数据 |
| [Sendra Shipping Rules](https://wp-plugins-directory.com/sendra-shipping-rules-for-woocommerce) | 邮政重量价目表、体积重 | 同上，且更偏「规则引擎」而非「报价单」 |

**共同问题**：它们的抽象是「条件 → 价格」，而货代报价单的抽象是「分区 × 重量段 × (单价, 挂号费, 操作费, 最低消费)」。
维度不对齐，所以永远在手工搬运数据。改一次价格，几十上百个格子重填一遍。

### 2. 物流商 / 服务商对接插件（有，但覆盖窄，且不解决"报价单"）

- **CZLExpress（顺丰小包）**：[开源 WooCommerce 插件](https://github.com/woodchen-ink/czlexpress-for-woocommerce)，客户填地址后自动调 API 出价，还能在运费上加价（支持 `10% + 10` 这类表达式）。
- **YunExpress（云途）**：通过 [AfterShip / Postmen 的物流商应用](http://www.aftership.io.s3-website-us-east-1.amazonaws.com/zh-hans/shipping/carriers/yunexpress/) 接入 WooCommerce，属于第三方 SaaS 中转。
- **FreightAmigo**：[WooCommerce 插件](https://www.freightamigo.com/sc/ecommerce/woocommerce/)，多家承运商即时比价 + 建单 + 轨迹。
- **4PX（递四方）**：WooCommerce 生态里基本只有[轨迹查询类插件](https://www.parcelpanel.com/couriers/4px/)，没有官方报价插件。
- **WooliiPorter**：[中国仓履约插件](https://wordpress.org/plugins/wooliiporter-fulfillment/)，按打包实测重量和尺寸出报价，但运费是**下单后逐票确认、不预收**。

**共同问题**：
1. 一家一个插件，你有 3 条线路就要装 3 个，前台可能出现 3 种不同的价格逻辑。
2. 走 API 意味着**必须有该物流商的正式账号和授权**；很多卖家实际是走货代/二级代理，拿不到 API。
3. 报价单里那些「隐形规则」（挂号费按件、最低消费、燃油按月调、偏远按邮编）API 经常不返回，或者返回的是代理价。
4. 依赖外部服务，接口一改就挂，且价格不透明、不好对账。

### 3. 台湾/香港的本地化插件（思路对，但市场不对）

[Good Shipping](https://mrgood.com.tw/product/good-shipping/)——以中华邮政 EMS 费率为基础，按收件国自动分区，处理超重分箱和材积计价。
这是「按邮政/快递费率表 + 分区 + 材积」的正确抽象，但费率内置的是台湾邮政，不是大陆货代的报价体系。

### 4. 聚合平台 / ERP（能算，但人被绑走了）

ShipStation、Easyship 这类聚合平台能接 50+ 承运商，[也有文章提到云途/燕文/递四方"已提供官方插件"](https://www.10100.com/encyclopedia/explain/65672213)——
但实际能落地的多是 ERP（店小秘、马帮、易仓）或 SaaS 侧的对接，不是 WordPress 插件本身。

而[一线卖家的实操经验](https://www.micronet.com.cn/News/201611221007474.html)其实很直白：
> 去找有没有已对接的物流商的插件，像云途、燕文这些，跳转到对应平台注册拿 API 授权，回填写进去。第三步，设运费模板……

——**前提是"有"**。而现实是：小卖家拿不到 API，只能照着报价单手抄。

## 真实的痛点画像

一个典型的大陆跨境卖家：

- 用 WooCommerce 建站，收 USD / EUR。
- 发货走 1～3 家货代（云途、燕文、递四方、顺丰小包、或本地专线）。
- 每家给一张 Excel 报价单：10 个分区 × 每 0.1kg 一档（到 2kg 就是 20 档）= 200 个格子，还可能分普货/带电/敏感货三张表。
- 报价单**每月甚至每周变**（燃油、旺季附加费）。
- 现在的工作流：手动算好每个格子的价 → 在 Table Rate 插件里一格一格填 → 报价单一变，全部重来。

所以真正的需求不是"再做一个运费计算器"，而是：

> **把报价单原样贴进来，剩下的交给系统。**

## 产品定位

**「报价单 → 运费规则」的转换器。**

- 不绑定物流商，因为报价单本身是通用语言。
- 不联网、不调 API，所以不依赖账号、不依赖别人的接口稳定性。
- 一条线路 = 一个物流产品，卖家自己维护，改价 = 重新导一次 CSV。

### 与现有插件的差异

| 维度 | 通用费率表插件 | 物流商 API 插件 | 本项目 |
| --- | --- | --- | --- |
| 数据来源 | 手工逐条填 | 实时 API | **货代报价单 CSV** |
| 分区概念 | 靠配送区域硬凑 | 有 | **有，且可 `*` 兜底** |
| 挂号费/操作费 | 无（要算进单价） | 不一定返回 | **独立字段，逐票计** |
| 最低消费 | 无 | 不一定 | **有** |
| 燃油/偏远 | 无 | 不一定 | **有** |
| 体积重 | 少数有 | 有 | **有，系数可配** |
| 多币种 | 无 | 部分 | **有汇率换算** |
| 换价成本 | 全部重填 | 0 | **重导一次 CSV** |
| 依赖外部服务 | 否 | 是 | **否** |

## 已实现的功能（v0.1.0）

1. **线路管理**：一条线路 = 一套完整的计价配置（币种、汇率、体积重系数、进位规则、附加费）。
2. **CSV 报价单导入**
   - 中英文表头自动识别（分区/区域/zone、单价/价格/元每kg、挂号费、操作费、最低消费……）
   - UTF-8 / UTF-8 BOM / GBK（中文 Excel 默认编码）
   - 逗号 / 制表符 / 分号
   - 重量段写作 `0.001-0.1` 一列，或拆成上下限两列
   - 分区列留空自动沿用上一行（适配合并单元格导出）
   - 导入前预览 + 重叠区间警告 + 缺国家提示
3. **两种计价模型**
   - 重量段查表：`运费 = 该档单价 × 计费重 + 挂号费 + 操作费`，不足最低消费补足
   - 首重 + 续重：`首重价 + ceil((计费重 - 首重)/续重步进) × 续重价`
4. **体积重**：`长×宽×高 ÷ 系数`，取实重与体积重较大值；系数 6000/5000/8000 可配，填 0 关闭。
5. **重量进位**：0.001 / 0.01 / 0.1 / 0.5 / 1 kg，进位 / 四舍五入 / 精确；带浮点误差保护（0.1+0.2 不会被进位成 0.31）。
6. **附加费**：燃油（百分比）、偏远地区（按分区配置的国家列表）、每票固定处理费、最低消费。
7. **汇率换算**：报价币种 → 商店币种，一处配置全局生效。
8. **后台试算器**：目的国 + 实重 + 尺寸 → 命中分区、实重/体积重、计费重、逐项费用、换算后总价。
9. **WooCommerce 配送方式**：可放进任意配送区域；支持满额免运费；可选在结算页展示费用明细；算不出价时按设置隐藏或提示。
10. **HPOS 兼容**（WooCommerce 自定义订单表）。

## 技术设计要点

### 数据模型

```
cbsr_carriers   线路：币种、汇率、体积重系数、进位规则、附加费、状态、是否默认
cbsr_zones      分区：分区号、覆盖国家、偏远国家、计价方式、首重/续重参数
cbsr_rates      重量段：分区号、重量上下限、单价、挂号费、操作费、最低消费
```

用自定义表而不是 option/JSON：一张报价单动辄上百行，存表里才能按分区筛选、按重量排序、批量替换。

### 区间语义

报价单写 `0.001-0.1`、`0.101-0.2`，语义是 `(上一档上限, 本档上限]`。
所以匹配规则是：**取第一条 `weight_max >= 计费重` 的记录，再校验计费重不低于该档下限**。
这样 0.1kg 落进第一档、0.2kg 落进第二档，和货代的算法一致。

### 计算顺序

```
实重 + 包装重
  ↓ 与体积重取大 → 进位 → 计费重
  ↓ 按目的国找分区（精确匹配优先，* 兜底）
  ↓ 按分区计价方式算基础运费（+挂号费+操作费，补最低消费）
  ↓ + 燃油%（按基础运费）
  ↓ + 偏远附加费（目的国在分区偏远列表内）
  ↓ + 固定处理费
  ↓ × 汇率 → 商店币种
```

所有中间结果（体积重、计费重、逐项金额）都返回给调用方，可以在后台试算器和结算页明细里展示——对账时这一点很重要。

### 可扩展点

- `cbsr_package_data`：接管包裹数据（接真实装箱算法，或按商品额外加包装）。
- `cbsr_package_dimensions`：单独接管尺寸。
- 计价引擎是纯 PHP，不依赖 WordPress，可以直接单测（本项目带 95 项断言，见 `tests/`）。

## 后续路线

**v0.2 对账与成本**
- 订单运费 vs 实际账单的差额报表（哪个格子填错了，一眼看出来）
- 报价单版本管理（改价留痕，可回滚）
- 分区国家从 WooCommerce 国家列表里勾选（现在要手打两位码）

**v0.3 更贴近真实报价单**
- Excel (.xlsx) 直接导入，不用手动另存 CSV
- 多工作表 / 多级表头（货代报价单常见：第一行国家、第二行分区、第三行重量段）
- 商品维度：普货 / 带电 / 敏感货 / 液体，按 SKU 或分类切换报价表
- 分箱：超重自动拆成多票（`材积 + 单票限重` 是真实约束）

**v0.4 接通路**
- 物流商 API 适配层（云途、燕文、4PX、顺丰小包），作为"报价来源"的另一种实现，与 CSV 并列
- 生成运单、回写单号、轨迹同步（这才是大多数"物流插件"在做的事，但应该建立在算对价之后）

**v0.5 运营**
- 批量改价（油价联动、旺季系数）
- 多站点/多仓库
- 权限分离（运营改价、财务看报表）

## 一句话答复

市面上没有「把国内货代报价单直接变成 WooCommerce 运费规则」的插件，
现有的要么是通用费率表（要手填），要么是绑死某家物流商的 API 对接（要账号、要授权、覆盖窄）。
这个空白是真实的，而且切口很明确：**做报价单的解析与计价，而不是再做一遍配送方式。**
